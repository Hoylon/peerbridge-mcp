# PeerBridge Alpha 5.2 GitHub Demo Storyboard

Target length: 2 minutes 40 seconds

Purpose: show the real Alpha 5.2 workflow quickly enough for a GitHub visitor to understand
why PeerBridge is more than a terminal multiplexer or multi-model chat page.

## Recording sequence

| Time | Screen | Narration and proof point |
| --- | --- | --- |
| 0:00-0:15 | Native PeerBridge Control Room opens | "PeerBridge is a local-first control room for several AI coding Agents, their evidence, and the human decision that governs their work." |
| 0:15-0:30 | Scroll the permanent sidebar; open the current-panel guide | Show that all 12 panels are discoverable. Open one privacy-safe illustrated guide and match callouts 1, 2, and 3 to its steps. |
| 0:30-0:50 | Open **07 Providers** | Point out that model-route cards do not prove a CLI is installed. Show detected terminal states, the explicit Kimi confirmation path, and the official Grok Windows guide. Explain that PeerBridge has verified the installed ACP/MCP path but will not auto-run a publisher script whose executable SHA cannot be pre-bound. |
| 0:50-1:20 | Open **01 Multi-Agent Console** | Start two reviewed CLIs in a disposable demo repository. Show stable side-by-side panels, then switch to Focus and Timeline. State clearly that only captured output and events are visible, never hidden reasoning. |
| 1:20-1:45 | Open **02 Chat** | Put two routes into one room, select provider/model/reasoning per seat, and run one bounded round. Show the round and message limits before sending. |
| 1:45-2:10 | Open **09 Trust & Task Verification** | Show the operation state, Trust Timeline, exact source binding, human decision, and create-only Proof Bundle. Explain that a changed source makes old evidence stale. |
| 2:10-2:28 | Open **11 Usage** | Switch Today, Last 7 days, Last 30 days, and All time. Show hourly, daily, and monthly buckets and the explicit unavailable-token count. |
| 2:28-2:40 | Return to the Control Room overview | "One local place to run, compare, govern, and verify heterogeneous AI Agents. Alpha software, with evidence boundaries shown honestly." Display the GitHub repository and Windows portable download location. |

## Capture rules

- Record only a disposable demo repository and synthetic task. Do not show personal paths,
  API keys, account names, provider balances, cookies, or real project data.
- Keep cloud collaboration disabled. The demo may show the cloud-ready event boundary but
  must not imply that multi-machine sync ships in Alpha 5.2.
- Do not claim that PeerBridge displays an Agent's private chain-of-thought. Say "captured
  terminal output, tool activity, explicit summaries, and final answers."
- Do not click an installer during the recording. Show that installation is explicit and
  separately confirmed.
- Use Traditional Chinese narration with burned-in English subtitles, then export a second
  English-captioned version if time permits.
- Use 1080p at 30 fps, enlarge the pointer, and keep each click visible for at least one
  second. Avoid fast zooms and decorative transitions.

## GitHub delivery

- Do not commit the MP4 into Git history.
- Upload the approved video as a GitHub Release asset or to a stable video host, then place
  a real Control Room thumbnail near the top of the README and link it to the video.
- Keep a short silent GIF only if it stays small enough for fast README loading; the full
  narrated demo remains the primary explanation.
- Record only after the frozen QA executable passes physical review, so the video matches
  the downloadable build.
